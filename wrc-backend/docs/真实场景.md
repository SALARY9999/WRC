# 无人车避障真实场景说明

## 1. 系统定位

本系统不是“持续自动驾驶”，而是无人车在已有指挥航线上的**临时避障接管系统**。

## 2. 真实运行模式

1. 指挥所/指挥部下发航线，无人车按原航线正常行驶；
2. 我方推理系统持续检测前方障碍；
3. 检测到需要避障时，发送 `control_flag=1`（接管）；
4. 无人车改为执行我方下发的 64 个推理航点绕障；
5. 绕过障碍后发送 `control_flag=0`（释放），无人车恢复执行指挥部原航线。

我方闭环验证的终点是：**航点成功发到无人车 UDP 7010**。车辆端是否解析、执行、是否真正回原航线，不在我方代码可验证范围内。

## 3. 端到端数据流

### 3.1 位姿链路（已跑通）

```text
车辆 vehicle_state JSON
  → PGX UDP 7001（UdpPoseListener）
  → PoseHistory
```

时间戳现状：

- 车辆已提供 Unix 采集时间。相机使用 CIMG 包里的 `capture_time_ns`，整除 1000 得到微秒。
- 位姿使用车辆 Unix timestamp（秒），乘 1_000_000 得到微秒。两路是同一条 Unix 时间轴。
- 保留原始车辆 timestamp 在 `payload_timestamp_us`。不再切换时钟，也不再用包到达时间代替采集时间。

### 3.2 图像链路（CIMG）

`run_backend_real.sh` 直接启动 CIMG 接收端。车辆把 4 路 JPEG 打成一条 CIMG TCP 流推到服务器 `0.0.0.0:30106`。相机映射是 `1,2,0,4`。`camera/cimg_source.py` 收包、解码，`camera/sync.py` 组成 4 路 × 4 帧窗口。相机时间固定为 `capture_time_ns` 换算后的微秒。

### 3.3 模型推理链路（已跑通，时间轴统一在车辆 Unix 时间上）

```text
CameraWindow（4 相机 × 4 帧）
PoseHistory（按 t0 插值 16 步历史）
  → AlpamayoRunner.infer
  → 输出 64 个未来轨迹点（0.1s 间隔，共 6.4s）
  → local_xy_to_latlon 转经纬度
  → WaypointSender 打包
```

### 3.4 航点输出链路（已跑通到我方侧）

```text
PGX WaypointSender
  → 无人车 UDP 7010（config network.waypoint，当前 168.130.182.10:7010）
```

## 4. 数据格式

| 数据 | 格式 | 说明 |
|---|---|---|
| 位姿 | JSON `vehicle_state` | `timestamp`(Unix 秒)/lat/lon/azimuth(0=正西,90=正北,顺时针)/vNorth/vEast；chassis 嵌在 `pose` 内 |
| 图像 | CIMG TCP，4 路 JPEG → BGR 576×320 | 唯一相机入口，映射 `1,2,0,4` |
| 模型输入 | 4 相机 × 4 帧 + 16 步历史位姿 | Alpamayo 1.5 |
| 模型输出 | 64 点 x/y（t0 自车系） | 0.1s 间隔 |
| 航点 UDP | `magic/control/seq/vehicle_id/n` + lat/lon | `control_flag`: 0=不接管，1=接管 |

## 5. 模型能力边界（真实情况）

| 能力 | 模型是否原生支持 | 现状 |
|---|---|---|
| 视觉障碍感知 + 输出未来轨迹 | 支持 | 已跑通 |
| 接收指挥航线/导航指令 nav_text | 支持（route token） | 实车配置未启用 `ALPAMAYO_NAV_TEXT` |
| 自主判断“是否需要接管” | 不原生可靠 | 当前为关键词规则兜底 |
| 绕障后并回原航线 | 取决于是否输入原航线 | 当前未实现 |

## 6. 已确认/已修改

- 实车闭环曾在 2026-09-09 17:53–18:06 完整跑通；
- 当前相机和位姿都使用车辆 Unix 时间，统一为微秒；车辆原始时间戳仍保留在 `payload_timestamp_us`；
- 实车核对 `azimuth=0` 为正西、`90` 为正北、`180` 为正东、`270` 为正南（顺时针）；
- 后端把它换成罗盘航向 `(azimuth - 90) % 360` 后再给模型历史和输出经纬度，两边共用这一航向；
- 相机窗口身份来自 CIMG 包的 `sequence`（`cam<ID>:s<sequence>`），采集时间来自 `capture_time_ns`；
- 已加入相机断流检测和窗口保鲜保护；
- 代码仓库已统一到 `/data/users_data/wanghaohao/701/alpamayo_infer_backend`。

## 7. 已知断点 / 待解决问题

1. 相机与位姿都使用车辆 Unix 时间。两路时间差过大时本轮不推理；
2. CIMG 接收一次只服务一个连接。半开连接会挡住重连，读超时目前是 15 秒；
3. 推理耗时约 5–6 秒，航点下发时相对 t0 已滞后；
4. 航向只使用车辆上传的 `pose.azimuth`（先减 90° 换成正北为零的罗盘角），不再使用速度方向 COG；额外安装偏角由 `config/config.json` 的 `vehicle_heading.azimuth_offset_deg` 统一配置；
5. 接管判定做过 prompt A/B 实验：`first_line` 命中率 0/10，`prefill` 命中率 4/10 但 6/10 破坏轨迹生成；当前默认 `cot_rules` 已升级为“风险评分 + 阈值 + 否定词处理”，18/18 标注样本判定正确，并在 `infer-record` 记录 `risk_score / rule_hits`；
6. 指挥航线（nav_text）尚未作为模型输入；
7. 车辆端推流/接收/执行源码不在我方手中，最终执行无法验证。
